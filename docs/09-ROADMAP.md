## 1. 分档原则

- 每一档都能**独立可玩**，不是"半成品拼到最后一起验收"。
- 每档结束跑一次 `C-08` 的自查清单 + `go test` / `go vet` / `doc-check`。
- 涉及协议面的档，先在服务端仓库里找到对应的验收脚本，照着它的输出对字段。
- 每档都给一个能直接运行的 release 包；不给「只有开发机能跑」的中间态。

## 2. M1 · 终端骨架与主循环

| 项 | 结果 |

| 可运行 | `go build -o bin/playcli . && ./bin/playcli --server ws://127.0.0.1:8080`；`--login` / `--create` / `--page` / `--move` / `--snapshot` / `--gui` / `--tui` 为联调参数 |

| 鼠标与智能选择 | 点击行选中、双击执行；断路出口自动跳过、坊市优先买得起；新增 5 项测试 |

| 发布目录 | `make dist` 组装启动器 + `game/gamehost.exe` + `game/playcli.dll` + assets + manifest；宿主加载 DLL |

**工程**：`go.mod`（websocket + term + x/sys）、`proto.go` 全部帧类型、`net.go` 握手与重连、
`state.go` 状态归并、`app.go` 的按键→意图→网络命令循环、`render.go` 标题栏 + 三盒布局、
`pages.go` 数据页与舆图、`screen.go`/`widgets.go` 字符屏与盒子组件，
登录页/建号页/主界面/数据页/舆图/聊天输入。

**玩法**：登录、建号、`ready` 目录、日志、状态条、出口列表、移动、历练、打坐、突破。

**完成定义**

- 冷启动到"能移动"不超过 3 秒（release 包，SSD）。
- 终端 80×24 与 120×40 下布局都不截断；中英混排按显示宽度对齐。
- 待机（无倒计时）CPU < 1%，不持续重绘。
- `move` 有倒计时，到达前出口列与地点动作置灰；地形门槛在出口行就能看到缺什么。
- 打坐开关与 `vital` 校准一致；突破失败有明确文案。
- 断网 3 秒内自动重连，重连后 `ready` 整体替换状态；顶栏灯色正确。
- 日志 5000 行时滚动跟手，上滚不被新行抢位置。

## 3. M2 · 战斗与秘境

**状态：战斗已接入（2026-11-23）**。`battle` 帧解析、右侧战斗面板（敌方逐只量表、
1–9 选目标、队友血条）、`a/s/f` 操作、`over` 帧收盒；奇遇 `event` 弹层同时接入。
战报本身已经是逐条日志（服务端一次推多行，客户端全部追加），缺的是"逐行播放"的打字机效果；
秘境与掉线重连回层仍未做。

**工程**：`app.go` 的战斗按键与 `over` 判定、`render.go` 的 `drawBattleBox` 与 `drawEncounter`。

**玩法**：`battle`（单怪/三怪/组队）、目标选择、逐行战报、秘境进出与切层、掉线重连回层。

**完成定义**

- 三怪场景能按 `1`–`3` 或 `Tab` 选目标；目标死亡自动切下一只；`over` 后出手行禁用。
- 战报每轮追加一行（约 250ms 一行），`Esc` 可一次补全；跳过不影响状态。
- 秘境掉线 5 分钟内重连能回到同层同进度；清层不自动推进。
- 团灭与通关的文案、次数变化与服务端一致。
- 队友血条只在有数据时出现。

## 4. M3 · 社交与经济

**状态：坊市货架已提前落地（2026-11-23）**。`F5` 读 `ready.catalog.shop`，
`↑↓` 选、`+/-` 调数量、`Enter` 买入（`buy`）；买不起与阶位不够客户端先拦。
挂单 / 我的 / 价格曲线 / 拍卖 / 邮件仍在 M3。

**工程**：`app.go` 的列表光标与买卖意图、`render.go` 的定宽列与货架页、
`proto.go` 的 `catalog` 视图；后续社交页沿用同一套列表规矩（按显示宽度补齐、
`▸` 标光标、`PgUp/PgDn` 十格）。

**玩法**：聊天四频道与屏蔽、好友/师徒/关系、队伍与掉落模式、交易行、邮件、拍卖。

**完成定义**

- 好友离线申请、离线收信都能重连后看到。
- 交易行费率与在售上限来自帧，不写死；自己不能买自己的单（该操作弱化并写原因）。
- 抽签公告原样展示（含两人点数与得主）。
- 价格曲线 `null` 断线处理，不补 0；选中行能在详情里读出当天均价与成交量。
- 表格排序/筛选/列宽在切页后保留；200 行以内不分页。

## 5. M4 · 宗门、拍卖与实时切磋

**玩法**：宗门建/捐/审批/名单、宗门战全流程、拍卖出价/一口价、`live` 实时切磋。

**完成定义**

- 宗门战名单锁定后不可改，锁定态在界面上明确；战果双方可读。
- 拍卖被超价后余额正确退回（刷新 `state` 后一致）；到期结算不本地伪造。
- 实时切磋：15 秒倒计时准确（误差 ≤ 200ms），双方出手才推进，认输/掉线/超时都有明确结果与原因。
- 切磋中切页或改终端尺寸不打断倒计时，回到主视图状态正确。

## 6. M5 · 打磨与发布

**范围**：浅底配色方案、终端尺寸自适应（80×24 → 200×60）、可访问性（全键盘覆盖/高对比/可关动画）、
快照测试补全、日志搜索与复制、三平台打包（单二进制 + shell 补全）、
性能记录与长挂机报告。

**完成定义**

- 2 小时挂机 RSS 平稳（增长 < 15%）；待机 CPU < 1%。
- 80×24 到 200×60 全部可用：窄屏单行状态摘要，宽屏左右分栏，见闻吃剩余高度。
- 浅底配色下正文对比度 ≥ 4.5:1。
- 所有拒绝都有具体原因，不出现「操作失败」。
- 三个平台各一个可直接运行的产物，README 写清如何放行 SmartScreen / Gatekeeper。
