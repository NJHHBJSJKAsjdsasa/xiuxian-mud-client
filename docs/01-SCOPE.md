## 1. 一句话

做一个**能长时间挂机、也能认真打架**的修仙终端客户端：左边读得下去，右边点得动，断了能自己接上，一个二进制拷走就能跑。

## 2. 形态：Rust + TUI

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Rust（edition 2021） | 单二进制、无运行时；异步与 WS 生态成熟；崩溃面比脚本小 |
| 界面 | 终端 UI（ratatui + crossterm） | 游戏本体是文本 + 表格 + 节点图；终端是最短路径 |
| 并发 | tokio（多线程运行时） | 一条读、一条写、一个 tick；与协议的心搏/超时天然对齐 |
| 传输 | tokio-tungstenite + rustls | 与服务的 `/ws` 直连，不依赖 OpenSSL |
| 序列化 | serde + serde_json | 协议是 JSON；`#[serde(other)]` 忽略未知字段 |
| 平台 | Windows / macOS / Linux | 首版三平台；Windows 是当前开发机 |

**为什么不是网页**：网页要把"日志 + 表格 + 键盘操作"重新搭一遍（DOM、CSS、字体、跨域、浏览器兼容），
而终端已经在这些事上做到位了；这个游戏的界面复杂度不值得为它引入浏览器。
协议层不依赖终端，将来要做图形版（egui/iced）时 `net/` 与 `store/` 可以原样搬。

## 3. 目标（M1–M5）

1. **主循环可玩**：登录 → 建号 → 看节点 → 赶路 → 历练 → 打坐 → 突破。
2. **战斗可读**：多人遭遇、目标选择、战报逐行播放、秘境分层与掉线重连。
3. **社交与经济可用**：聊天、好友、师徒、队伍、交易行、邮件。
4. **宗门与拍卖可用**：建宗/捐献/宗门战报名与战报、拍卖出价与一口价。
5. **实时切磋**：`live` 帧驱动的回合制对战，15 秒窗口、倒计时、认输。

## 4. 非目标（首版明确不做）

| 不做 | 原因 |
|---|---|
| 网页版 / 浏览器 | 首版用 TUI；图形版留到以后（协议与状态层可复用） |
| 本地战斗计算 | 服务端是唯一事实源；客户端只播 `battle` / `live` / `pvpResult` |
| 离线收益模拟 | 离线收益由服务端在 `ready.offline` 给出 |
| 宏 / 自动脚本 | 与服务端限流和"手动选择"的玩法前提冲突 |
| 多账号同屏 | 一账号一连接（顶号机制） |
| 图片 / 音效 | 终端里没有；ASCII 图标与色彩足够表达地形与状态 |
| 国际化 | 文案全部中文；CJK 宽度由 `unicode-width` 处理，不做多语言 |

## 5. 成功标准（可验收）

- 冷启动到可操作 ≤ 2 秒（本地网络，含登录与 `ready`）。
- 主循环（登录 → 移动 → 战斗一场 → 打坐）无阻塞、无 panic、无花屏。
- 断线重连：3 秒内恢复；秘境掉线在 5 分钟内回同层（服务端口径）。
- 版本不兼容（关闭码 4004）时给"升级客户端"的明确提示，且**不进入重连循环**。
- 连续挂机 2 小时，RSS 不持续增长（日志环形缓冲 + 面板按需构建）。
- Windows/macOS/Linux 三平台各一个二进制，不要求安装运行时。

## 6. 依赖与前置

- 服务端可连：`/healthz` 200、`/ws` 可握手。
- 手里要有：服务端 `docs/05`（字段）、`docs/12`（流程）、本目录 `C-03`（连接策略）。
- 终端要求：支持 256 色与 UTF-8；Windows Terminal / iTerm2 / 常见 Linux 终端均可。
