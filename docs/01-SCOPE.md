## 1. 一句话

做一个**能长时间挂机、也能认真打架**的修仙终端客户端：日志读得下去，面板看得清，
断了能自己接上，一个二进制拷到 SSH 里就能跑。

## 2. 形态：Go + 终端（TUI）

| 项 | 选择 | 理由 |
|---|---|---|
| 语言 | Go 1.25 | 单二进制、无运行时；交叉编译一步到位 |
| 界面 | 手写 ANSI（`screen.go` / `widgets.go`） | 不引 TUI 框架：布局与边框自己画，行为可预测、SSH 一致 |
| 并发 | goroutine + channel | 一条网络、一条读，主 goroutine 做按键与重绘 |
| 传输 | `gorilla/websocket` + 标准库 `net/http` | 直连服务端 `/ws` 与 `/api/*`，不依赖系统库 |
| 序列化 | `encoding/json` | 协议是 JSON；未知字段默认忽略 |
| 平台 | Windows / macOS / Linux | 任何 UTF-8 终端；SSH 可玩 |

**为什么是终端**：这个游戏的玩法是"读文字、看格子地图、敲指令"，
字符界面能把这些表达清楚，而且**没有半吊子写实**——玩家看到的就是这个世界本身。
一屏字符就是一个世界，不用为视觉风格找借口；终端也天然贴合 MUD 的阅读节奏。

**为什么不是网页**：需要 WebView/Chromium，发布体积与安全面都不划算。

**为什么不用 TUI 框架**：tview / bubbletea 这类库会把布局、按键、刷新节奏都封起来，
排查"为什么这一行错了"要读框架源码；本项目的界面只有盒子、量表、列表三种原件，
手写两百行就够，还能对"每行宽度恰好等于终端宽"做单测。

## 3. 目标（M1–M5）

1. **主循环可玩**：登录 → 建号 → 看节点 → 赶路 → 历练 → 打坐 → 突破。
2. **战斗可读**：多人遭遇、目标选择、战报逐行播放、秘境分层与掉线重连。
3. **社交与经济可用**：聊天、好友、师徒、队伍、交易行、邮件。
4. **宗门与拍卖可用**：建宗/捐献/宗门战报名与战报、拍卖出价与一口价。
5. **实时切磋**：`live` 帧驱动的回合制对战，15 秒窗口、倒计时、认输。

## 4. 非目标（首版明确不做）

| 不做 | 原因 |
|---|---|
| 网页版 / 内嵌 WebView | 发布体积与安全面都不可接受 |
| 图片 / 立绘 / 音效 | 终端表达不了；也不打算用字符画冒充美术 |
| 本地战斗计算 | 服务端是唯一事实源；客户端只播 `battle` / `live` / `pvpResult` |
| 离线收益模拟 | 服务端登录时结算离线收益并随 `log` 下发，响应里没有专用字段 |
| 宏 / 自动脚本 | 与服务端限流和"手动选择"的玩法前提冲突 |
| 多账号同屏 | 一账号一连接（顶号机制）；多开会互相顶掉 |
| 音频 / 3D | 首版只有字符网格与文字 |
| 移动端 | 桌面终端优先；触屏布局不在首版 |
| 多语言 | 文案全部中文（UTF-8） |

## 5. 成功标准（可验收）

- 冷启动到可操作 ≤ 3 秒（含建连与首帧；SSD 机器）。
- 主循环（登录 → 移动 → 战斗一场 → 打坐）无卡顿、无 panic、无空白屏。
- 断线重连：3 秒内恢复；秘境掉线在 5 分钟内回同层（服务端口径）。
- 版本不兼容（关闭码 4004）时给"升级客户端"的明确提示，且**不进入重连循环**。
- 连续挂机 2 小时，RSS 不持续增长（日志环形缓冲 + 只渲染可视行）。
- 终端 80×24 到 200×60 之间布局不错位；中英混排按显示宽度对齐。
- Windows/macOS/Linux 各一个可执行产物，不要求用户装运行时。

## 6. 依赖与前置

- 服务端可连：`/healthz` 200、`/ws` 可握手。
- 手里要有：服务端 `docs/05`（字段）、`docs/12`（流程）、本目录 `C-03`（连接策略）。
- 终端：UTF-8、80×24 起；真彩优先，256 色可读。不需要显卡与图形驱动。
- 字体不是依赖：由用户终端提供等宽 CJK（更纱黑体 / Menlo / Consolas + 中文回退）。
