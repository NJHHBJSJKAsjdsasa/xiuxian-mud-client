## 1. 一句话

做一个**能长时间挂机、也能认真打架**的修仙文字客户端：左边读得下去，右边点得动，断了能自己接上。

## 2. 形态

| 项 | 选择 | 理由 |
|---|---|---|
| 运行环境 | 浏览器（桌面优先，移动端可用） | 协议是 JSON over WS，浏览器零安装 |
| 技术栈 | TypeScript + Vite；界面用原生 DOM + CSS；地图与战斗特效用 Canvas 2D | 文本为主，重框架只会增加状态同步成本 |
| 分发 | 静态文件；后续可套 Electron / Tauri | 同一套代码，先不为壳做妥协 |
| 离线能力 | 无。断线即停止推演，重连后以服务端快照为准 | 本地推演收益低、错一次全盘皆错 |

## 3. 目标（M1–M5）

1. **主循环可玩**：登录 → 建号 → 看地图 → 赶路 → 历练 → 打坐 → 突破。
2. **战斗可读**：多人遭遇、目标选择、战报逐行播放、秘境分层与掉线重连。
3. **社交与经济可用**：聊天、好友、师徒、队伍、交易行、邮件。
4. **宗门与拍卖可用**：建宗/捐献/宗门战报名与战报、拍卖出价与一口价。
5. **实时切磋**：`live` 帧驱动的回合制对战，15 秒窗口、倒计时、认输。

## 4. 非目标（本期明确不做）

| 不做 | 原因 |
|---|---|
| 3D / 等距地图渲染 | 世界是节点图，不是连续空间；画成俯视拓扑已够读 |
| 客户端本地战斗计算 | 服务端是唯一事实源；客户端只播 `battle` / `live` / `pvpResult` |
| 离线收益模拟 | 离线收益由服务端在 `ready.offline` 给出 |
| 机器人 / 自动脚本 | 与"手动选择"的玩法前提冲突，且会踩服务端限流 |
| 多账号同屏 | 一账号一连接（顶号机制），不做多开管理 |
| 国际化 | 文案全部中文，先不抽 i18n 骨架 |

## 5. 成功标准（可验收）

- 冷启动到可操作 ≤ 3 秒（本地网络，含登录与 `ready`）。
- 主循环（登录 → 移动 → 战斗一场 → 打坐）无阻塞、无报错弹窗。
- 断线重连：3 秒内恢复；秘境掉线在 5 分钟内回同层（服务端口径）。
- 版本不兼容（关闭码 4004）时给"升级客户端"的明确提示，且**不进入重连循环**。
- 连续挂机 2 小时，内存不持续增长（日志列表有上限、面板懒加载）。
