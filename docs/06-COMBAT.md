## 1. 三种战斗形态

| 形态 | 帧 | 结算方式 | 客户端要做 |
|---|---|---|---|
| 打怪（单体/多怪） | `battle` | 逐回合，玩家每回合出手 | 怪卡横排、目标选择、逐行战报 |
| 全模拟 PvP | `pvpResult` | 一次算完 | 逐行播放战报，展示 `winSide` / `turns` / 校验和 |
| 实时切磋 | `live` | 每回合双方各出一手 | 回合数 + 倒计时条、出手键、结算面板 |

三者共用同一个「战斗区」：战斗开始时**场景段让位**给战斗面板（8–14 行，按终端高度取），
见闻段与提示行不动——打架时仍要看得见战报与自己的血条。
战斗结束后场景段恢复。不做全屏模态，也不新开页面。

## 2. `battle` 帧

关键字段（详见服务端 `P-MSG-02` 与 `buildBattle`）：

- `round`、`over`、`won`、`id`
- `foes[]`：`{i, name, hp, max_hp, lvl, dead, status[]}`；多怪时按 `i` 区分
- `enemy`：第一只活着的怪（旧客户端兼容字段）
- `allies[]`：`{name, hp, max_hp, down}`（多人遭遇）
- `me`：自己的气血真气

客户端规则：

1. **不重算伤害**：帧里给了血量就照着掉；血条用字符格数表示，数字立即变。
2. **目标选择**：出手时带 `target`（怪的序号）；不选则默认第一只活怪。
   当前目标用整块反色 + 卡首 `▸` 标出，一眼可辨。
3. **`over` 之后**：出手行整行置灰并在提示行写「战斗结束」，等 `state` 或 `log` 的结算播报，不要自动连战。
4. **逃跑**：`battle.op=flee`，成功后等 `over` 帧（`fled:true`），不要本地直接关面板。

战斗面板结构（等宽字符，宽度不足时怪卡改为竖排逐只）：

```
 第 3 回合                                            真气 61/100
▸┌ 1 山魈 L3 ──────┐ ┌ 2 山魈 L3 ──────┐ ┌ 3 石灵 L2 ──────┐
 │ 血 [######----] 62│ │ 血 [###-------] 31│ │ 已倒下          │
 │ 中毒 3            │ │                   │ │                 │
 └───────────────────┘ └───────────────────┘ └─────────────────┘
 队友 阿岚 [#######-] 78   青禾 已倒下
 ──────────────────────────────────────────────────────────────
 [1 落石术] [2 御风斩] [3 打坐] [4 服丹] [f 逃跑]
```

- 怪卡固定宽度（默认 20 列，含边框），名字按显示宽度截断；死亡后卡内写「已倒下」并用弱化色。
- 目标切换：`←` `→` 或 `Tab` 在活怪间循环，直接按 `1`–`9` 选第 n 只；目标死亡后自动选下一只活怪。
- 技能行显示冷却剩余秒数（`[1 落石术 3s]`），不可用时整段用弱化色，但秒数照常走。
- 队友血条只在 `allies[]` 非空时出现，占一行。
- 战斗面板内的键位与主界面一致（`Space` 普攻 / `1`–`9` 技能 / `f` 逃跑），不另记一套。

## 3. 全模拟 PvP（`pvpResult`）

- 帧到即播：先显示「谁对谁、几打几」，再逐行追加战报，最后给胜负与积分变化。
- 校验和只展示不校验（服务端已核）；展示它是为了「同一场双方看到的战报一致」这一信任感。
- 生死斗有赌注：结算后必须刷新 `state`（灵石变了），不要用帧里的 `delta` 直接改本地数值。
- 播放中按 `Esc` 直接跳到最后一行（跳过只影响播放，不影响状态）。

## 4. 实时切磋（`live`）

- 帧：`{id, round, deadline, side, you{...}, foe{...}, over, winner, log[]}`。
- 每回合 15 秒；`deadline` 是服务端时间戳，倒计时用 `server_now()`。
- 出手：`live {op:"act", kind:"attack"|"skill"|"yield", skill?}`；同回合只能出一次。

界面：

- 顶栏右侧固定显示 `R3 07s`：回合数 + 剩余秒数；最后 5 秒数字转朱砂色（不做闪烁，终端里闪烁干扰阅读）。
- 双方各一块定宽信息块：道号、境界、气血/真气字符条、`已出手`/`等待` 标记。
- 自己出手后：技能行置灰，状态行写「等对手出手…」；对手出手后进入下一回合，技能行恢复。
- 掉线/被 GM 结束：`log` 里会给出原因（对手掉线 / GM 结束），结算文案要原样引用，不要只显示「你输了」。
- `over` 之后：显示 `winner` 与原因，并刷新 `state`（切磋不掉血，但战绩 `duels` / `pk` 变了）。

## 5. 秘境（`dg`）

- `enter` 需要队伍（队长发起）；每层要 `next` 才进下一层，**清层不自动推进**。
- 层进度写在地名行右侧：`秘境 第 2/5 层 ✓✓`；清层后提示行出现 `[n 下一层]` 与 3 秒提示（不自动发）。
- 掉线 5 分钟内重连回同一层同进度：重连后拉 `dg info`，若仍在实例里就直接渲染层进度。
- 每层 10 分钟上限、队伍全灭即结束：两种情况都以服务端 `log` 为准，客户端只做提示。
- 不要缓存「剩余次数」：次数在 `state`/`dg info` 里，切日会重置。

## 6. 赶路

- `move {to}` 受理后，用 `state.travel` 显示倒计时；`arrive_at` 是绝对时间。
- 到达前禁用依赖地点的动作（历练、副本、交易）：按键不响应，提示行写「正在赶路 00:07」。
- 到达后由服务端推 `state`/`log`；**不要本地切换节点**。
- 地形有门槛（悬崖要御风/金丹、河流要避水符/筑基）时，路标行直接显示缺口与所需物，而不是按下去才报 `E-TERRAIN`。
- 栈道收过路费：路标行显示「1 灵石」，灵石不够时该段用朱砂色，而不是让人试。
- 终端切到后台不影响赶路：时间由服务端时间戳算，回来时直接显示正确剩余（或已到达）。

## 7. 播放节奏

- 战报逐行追加：每轮主循环（30ms）最多追加一行到见闻段，整段不重排、不闪烁。
- `battle` 回合帧可能连发（多人遭遇里队友出手也会推帧）：播放队列按 `round` 合并，不排队积压。
- 播放中收到 `over` 帧时，把队列播完再收尾，不要丢掉最后几行。
- 播放节奏只是观感，**不得延迟状态更新**：血量在帧到达时即更新，播放队列只影响日志逐行显示。
- 日志区处于「用户上滚」状态时，新战报不抢滚动位置，只在提示行累加「↓ 3 条新见闻」。
