## 1. 三种战斗形态

| 形态 | 帧 | 结算方式 | 客户端要做 |
|---|---|---|---|
| 打怪（单体/多怪） | `battle` | 逐回合，玩家每回合出手 | 怪物卡、目标选择、逐行战报 |
| 全模拟 PvP | `pvpResult` | 一次算完 | 逐行播放战报，展示 `winSide` / `turns` / 校验和 |
| 实时切磋 | `live` | 每回合双方各出一手 | 回合倒计时环、出手条、结算面板 |

三者共用同一个"战斗区"：战斗开始时，中栏下半部（日志上方）滑入战斗面板，高度 280–360；
战斗结束后面板收起，日志回到原位。不做全屏模态——打架时仍要看得见日志与状态。

## 2. `battle` 帧

关键字段（详见服务端 `P-MSG-02` 与 `buildBattle`）：

- `round`、`over`、`won`、`id`
- `foes[]`：`{i, name, hp, max_hp, lvl, dead, status[]}`；多怪时按 `i` 区分
- `enemy`：第一只活着的怪（旧客户端兼容字段）
- `allies[]`：`{name, hp, max_hp, down}`（多人遭遇）
- `me`：自己的气血真气

客户端规则：

1. **不重算伤害**：帧里给了血量就照着掉；血条用 150ms 插值到新值，数字立即变。
2. **目标选择**：出手时带 `target`（怪的序号）；不选则默认第一只活怪。
   怪卡上必须始终能看出"当前目标"（主色描边 + 左上角三角标）。
3. **`over` 之后**：出手条禁用并淡出，等 `state` 或 `log` 的结算播报，不要自动连战。
4. **逃跑**：`battle.op=flee`，成功后等 `over` 帧（`fled:true`），不要本地直接关面板。

战斗面板结构：

```
┌──────────────────────────────────────────────────────────────┐
│ 第 3 回合                                      [逃跑 f]      │
│ ┌────────────┐ ┌────────────┐ ┌────────────┐                 │
│ │ 山魈  L3   │ │ 山魈  L3   │ │ 石灵  L2   │  ← 怪卡横排      │
│ │ ██████░░ 62│ │ ███░░░░░ 31│ │ 已倒下     │                 │
│ │ 中毒 3     │ │            │ │            │                 │
│ └────────────┘ └────────────┘ └────────────┘                 │
│ 队友：阿岚 ███████░ 78   青禾 已倒下                          │
│ ──────────────────────────────────────────────────────────── │
│ [1 落石术] [2 御风斩] [3 打坐] [4 服丹]        真气 61/100    │
└──────────────────────────────────────────────────────────────┘
```

- 怪卡 160×88：名字 + 等级、血条、状态 chip（中毒/眩晕等），死亡后整卡 40% 透明并加"已倒下"。
- 点击怪卡切换目标；`Tab` 在活怪间循环；目标死亡后自动选下一只活怪。
- 技能按钮显示冷却遮罩（扇形或自下而上的填充），不可用时置灰但仍显示冷却秒数。
- 队友血条只在 `allies[]` 非空时出现。

## 3. 全模拟 PvP（`pvpResult`）

- 帧到即播：先显示"谁对谁、几打几"，再逐行播放战报，最后给胜负与积分变化。
- 校验和只展示不校验（服务端已核）；展示它是为了"同一场双方看到的战报一致"这一信任感。
- 生死斗有赌注：结算后必须刷新 `state`（灵石变了），不要用帧里的 `delta` 直接改本地数值。
- 播放中可按 `Esc` 或点"跳过"直接看结果；跳过只影响动画，不影响状态。

## 4. 实时切磋（`live`）

- 帧：`{id, round, deadline, side, you{...}, foe{...}, over, winner, log[]}`。
- 每回合 15 秒；`deadline` 是服务端时间戳，倒计时用 `server_now()`。
- 出手：`live {op:"act", kind:"attack"|"skill"|"yield", skill?}`；同回合只能出一次。

界面：

- 顶栏中央显示倒计时环：外圈弧长随剩余时间收缩，中间是 `R3`；最后 5 秒变红并且每秒一次轻微脉冲（可被"减少动态效果"关掉）。
- 双方各一张大卡（240×120）：道号、境界、气血/真气条、已出手标记。
- 自己出手后：技能条置灰，状态文字变"等对手出手…"，环继续走；对手出手后进入下一回合，技能条恢复。
- 掉线/被 GM 结束：`log` 里会给出原因（对手掉线 / GM 结束），结算面板要原样引用，不要只显示"你输了"。
- `over` 之后：显示 `winner` 与原因，并刷新 `state`（切磋不掉血，但战绩 `duels` / `pk` 变了）。

## 5. 秘境（`dg`）

- `enter` 需要队伍（队长发起）；每层要 `next` 才进下一层，**清层不自动推进**。
- 层进度用顶部横条：`第 2/5 层` + 已清层打勾；清层后出现"下一层"按钮与 3 秒倒计时提示（不自动点）。
- 掉线 5 分钟内重连回同一层同进度：重连后拉 `dg info`，若仍在实例里就直接渲染层进度。
- 每层 10 分钟上限、队伍全灭即结束：两种情况都以服务端 `log` 为准，客户端只做提示。
- 不要缓存"剩余次数"：次数在 `state`/`dg info` 里，切日会重置。

## 6. 赶路

- `move {to}` 受理后，用 `state.travel` 显示倒计时；`arrive_at` 是绝对时间。
- 到达前禁用依赖地点的动作（历练、副本、交易），控件置灰并提示"正在赶路"。
- 到达后由服务端推 `state`/`log`；**不要本地切换节点**。
- 地形有门槛（悬崖要御风/金丹、河流要避水符/筑基）时，出口列表要显示缺口与所需物，而不是按下去才报 `E-TERRAIN`。
- 栈道收过路费：出口行要显示"1 灵石"，灵石不够时直接标红而不是让人试。
- 窗口失焦/最小化不影响赶路：时间由服务端时间戳算，回来时直接显示正确剩余（或已到达）。

## 7. 播放节奏

- 战报逐行播放：每行 140ms 淡入（透明度 0→1，位移 4px），插入日志顶部不跳动。
- `battle` 回合帧可能连发（多人遭遇里队友出手也会推帧）：播放队列按 `round` 合并，不排队积压。
- 播放中收到 `over` 帧时，把队列播完再收尾，不要丢掉最后几行。
- 播放节奏只是观感，**不得延迟状态更新**：血量在帧到达时即更新，播放队列只影响日志逐行显示。
- 日志区处于"用户上滚"状态时，新战报不抢滚动位置，只增加"回到底部"的计数。
