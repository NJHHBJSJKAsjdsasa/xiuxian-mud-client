## 1. 帧预算（桌面 60fps = 16.6ms）

| 工作 | 预算 | 超标时的做法 |
|---|---|---|
| store 更新 | ≤ 1ms | 大对象只换引用，不深拷贝 |
| 日志增量渲染 | ≤ 3ms | 虚拟列表，只渲染可视区 |
| 状态条 / 顶栏 | ≤ 1ms | 只在数值变化时写 DOM |
| 节点图重绘 | ≤ 6ms | 节点静态层缓存，重绘只画高亮与出口 |

**硬规则**：任何一条 WS 消息的处理不得触发整页重排；一律标脏 + rAF 合批。

## 2. 上限

| 项 | 上限 | 超出 |
|---|---|---|
| 日志行 | 5 000 行 | 丢最早，保留最后 |
| 面板 DOM | 8 个常驻 | LRU 销毁 |
| 节点图节点 | 90–200 | 静态层用离屏 Canvas 缓存 |
| 聊天历史 | 200 条/频道 | 丢最早 |

## 3. 测试矩阵

| 类别 | 用例 | 判定 |
|---|---|---|
| 握手 | 正常 `proto`；不带 `proto`；超版本 | 超版本必须显示升级提示且不重连 |
| 重连 | 拔网、切后台 30s、服务端重启 | 3 秒内恢复；`ready` 后界面与服务端一致 |
| 顶号 | 同账号第二个连接 | 旧连接提示"账号在别处登录"，不重连 |
| 战斗 | 单怪 / 三怪 / 组队遇战 / 团灭 | 帧序不丢、目标选择生效、`over` 后按钮禁用 |
| 实时切磋 | 双方出手推进、超时、认输、对手掉线 | 倒计时准确；结算有原因 |
| 秘境 | 进本、切层、掉线 5 分钟内重连 | 回同层同进度；超 5 分钟回不去 |
| 经济 | 挂单、撤单、成交、拍卖出价/被超 | 数值与服务端一致，不本地加减 |
| 长挂机 | 2 小时打坐 + 间歇战斗 | 内存平稳、日志截断正常 |

## 4. 复用服务端脚本做联调

服务端仓库 `tools/` 下的脚本可以直接当"对照答案"：

| 脚本 | 能验证客户端的什么 |
|---|---|
| `tools/smoke.mjs` | 登录/建号/打坐/历练的主链路顺序与字段 |
| `tools/travel-check.mjs` | `move` 的受理与到达时刻、地形门槛文案 |
| `tools/party-fight-check.mjs` | `battle` 多怪、目标选择、`pvpResult`、`live` 实时切磋的帧序 |
| `tools/gw-check.mjs` | 宗门战从下书到战果的完整帧 |
| `tools/market-check.mjs` | 交易行挂单/成交/历史的字段 |

做法：先跑脚本看服务端真实输出，再对照客户端渲染；两边不一致时以服务端为准。

## 5. 回放测试

- 把一次会话的 WS 帧录成 JSONL（`{dir:"in"|"out", ts, frame}`），在测试里重放到 store。
- 断言：最终状态与录制结束时一致；关键帧（`over`、`winner`、`duels`）都被消费一次。
- 回放文件不入库，只放 `client/test/fixtures/` 下的小样本（< 200KB）。
