## 1. 重绘预算

TUI 的"帧"是终端重绘，不是 GPU 帧。目标：**空闲 4 次/秒、战斗 10–15 次/秒**，每次 ≤ 2ms。

| 工作 | 预算 | 超标时的做法 |
|---|---|---|
| 事件处理（一帧内） | ≤ 0.5ms | 大 JSON 解析放 `spawn_blocking` |
| 布局计算 | ≤ 0.5ms | 只算可见区域，表格按窗口裁剪 |
| 渲染（ratatui buffer） | ≤ 1ms | 只画脏区；日志不整屏重排 |

**硬规则**：没有状态变化就不重绘；`vital` 每秒一条也只更新状态行，不整屏重画。

## 2. 上限

| 项 | 上限 | 超出 |
|---|---|---|
| 日志行 | 5 000 行 | 环形缓冲丢最早 |
| 聊天历史 | 200 条/频道 | 丢最早 |
| 面板表格 | 只渲染可视区 ± 10 行 | 不建全量 `Row` |
| 解码失败样本 | 10 条/会话 | 之后只计数 |

## 3. 内存

- RSS 目标：空闲 < 30MB，挂机 2 小时增长 < 20%。
- 不缓存整份 `state` 历史；只保留当前快照与必要派生（背包索引、技能名映射）。
- 日志行用 `String` 而非 `&str` 切片，避免生命周期牵连；单行长度上限 512 字符，超出截断。

## 4. 测试矩阵

| 类别 | 用例 | 判定 |
|---|---|---|
| 握手 | 正常 `proto`；不带 `proto`；超版本 | 超版本必须提示升级且不重连 |
| 重连 | 断网、挂起终端 30s、服务端重启 | 3 秒内恢复；`ready` 后界面与服务端一致 |
| 顶号 | 同账号第二个连接 | 旧连接提示"账号在别处登录"，不重连 |
| 战斗 | 单怪 / 三怪 / 组队遇战 / 团灭 | 帧序不丢、目标选择生效、`over` 后按键禁用 |
| 实时切磋 | 双方出手推进、超时、认输、对手掉线 | 倒计时准确；结算有原因 |
| 秘境 | 进本、切层、掉线 5 分钟内重连 | 回同层同进度；超 5 分钟回不去 |
| 经济 | 挂单、撤单、成交、拍卖出价/被超 | 数值与服务端一致，不本地加减 |
| 长挂机 | 2 小时打坐 + 间歇战斗 | 内存平稳、日志截断正常 |
| 终端 | 80×24 / 120×40 / 200×60；resize | 不错列、不花屏、不 panic |

## 5. 自动化怎么跑

```bash
cargo test            # 单元：协议解析、store 合并、时间偏移、CJK 截断
cargo test --test replay   # 帧回放（JSONL）
cargo clippy -- -D warnings
cargo fmt --check
```

- **协议解析**：把 `05` 里的样例帧写成 `tests/fixtures/*.json`，逐个反序列化并断言关键字段。
- **store 合并**：`state` / `vital` / `ready` 三种到达顺序，断言最终值一致。
- **时间**：固定 `ready.server_now` 与本地时钟，断言倒计时计算（不依赖真实时间）。
- **CJK**：`unicode-width` 截断/填充在"中英混排 + 生僻字"样本上逐字符断言。

## 6. 帧回放

- 录制：`--record frames.jsonl` 把收发的每一帧按 `{dir, ts, frame}` 写入文件。
- 回放：`cargo run -- --replay frames.jsonl` 驱动 store 与渲染，不连服务端。
- 断言：最终状态与录制结束时一致；关键帧（`over`、`winner`、`duels`）都被消费一次。
- 回放文件不入库，只放 `tests/fixtures/` 的小样本（< 200KB）。

## 7. 复用服务端脚本做联调

服务端仓库 `tools/` 下的脚本可以直接当"对照答案"：

| 脚本 | 能验证客户端的什么 |
|---|---|
| `tools/smoke.mjs` | 登录/建号/打坐/历练的主链路顺序与字段 |
| `tools/travel-check.mjs` | `move` 的受理与到达时刻、地形门槛文案 |
| `tools/party-fight-check.mjs` | `battle` 多怪、目标选择、`pvpResult`、`live` 实时切磋的帧序 |
| `tools/gw-check.mjs` | 宗门战从下书到战果的完整帧 |
| `tools/market-check.mjs` | 交易行挂单/成交/历史的字段 |

做法：先跑脚本看服务端真实输出，再对照客户端渲染；两边不一致时以服务端为准。
