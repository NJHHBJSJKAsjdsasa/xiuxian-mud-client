## 1. 刷新预算

主循环是**事件驱动**：按键、网络事件、250ms 定时器三者任一到达就画一帧。
没有"固定 30ms 轮询"，也就没有空转。

| 工作 | 预算 | 超标时 |
|---|---|---|
| drain 事件 + 状态合并 | ≤ 0.5ms | 一批 `log` 合并插入；一次最多消费 512 条 |
| 布局与渲染（100×30） | ≤ 2ms | 只渲染可见行；表格不做全量拼接 |
| 写屏（按行签名跳过未变化的行） | ≤ 1ms | 空闲时一帧 0 字节；只有光标定位与变化行 |
| 桌面窗口绘制 | 同帧哈希不变时跳过绘制，仅 BitBlt | 250ms 定时器与按键/鼠标事件触发；不重复画字形 |
| 整帧 | ≤ 4ms | 终端本身是瓶颈，客户端不抢 CPU |

**硬规则**：不因为"没变化"跳过整帧判断——渲染管线必须每轮都跑，
否则时间相关的倒计时不会推进；省字节靠行签名，不靠跳帧。

## 2. 上限

| 项 | 上限 | 超出 |
|---|---|---|
| 日志行 | 5 000 行 | 环形缓冲丢最早（`logBuf` 摊还 O(1)） |
| 单行日志 | 512 字符 | 服务端已截断；客户端渲染再按列截断 |
| 聊天历史 | 200 条 | 丢最早 |
| 可见日志 | 见闻盒高度 | 只取末尾 N 条，贴底 |
| 舆图节点 | 无上限 | 布局一次算完并缓存；节点 > 60 时缩小字号不做（终端无字号） |
| 网络事件队列 | 2 048 条 | 满了丢弃：界面每 250ms 重绘，丢一条不影响正确性 |

## 3. 内存与 CPU

- RSS 目标：空闲 < 20MB，挂机 8 小时增长 < 10%（Go 运行时本身约 5–8MB）。
- CPU：空闲时接近 0——没有定时轮询，只有 250ms 一次的 tick 与按键/网络事件。
- 终端无显存；桌面窗口只有一块后台位图（约 1320×850×4 ≈ 4.5MB）。
- 字符网格（100×30 = 3000 格）与日志缓冲是唯一常驻 UI 状态。
- 不缓存整份 `state` 历史；只保留当前快照与必要派生（舆图节点/边）。
- 日志条目只存 `logLine` 与实际时间戳，不做全文索引。

## 5. 自动化怎么跑

```bash
go test ./...              # 142 项：文本、字符屏、按键、状态、渲染、操作、快照、GUI、启动器参数、窗口模式、黑框拖动、DPAPI、账号合并、离开菜单
go vet ./...               # 静态检查
python tools/doc-check.py  # 文档矩阵与链接
```

- **文本**：`text_test.go` —— 显示宽度（中文 2 列）、按列截断、补齐、千分位、倒计时。
- **字符屏**：`screen_test.go` —— 宽字符占两格且续格标记为 0、每行等宽、
  截断不劈开汉字、脏行跳过（第二帧 0 字节）、颜色档位解析。
- **按键**：`keys_test.go` —— 方向键/翻页/Home/End/F1–F12、单独 ESC、
  UTF-8 汉字、控制字节、认不出的 CSI 整段吞掉。
- **状态**：`state_test.go` —— 日志环形上限与丢弃计数、`look` 不覆盖出口、
  `state` 全量替换、`vital` 回写、舆图节点与布局（有坐标 / 无坐标两路）、方位箭头。
- **渲染**：`render_test.go` —— 每行宽度不变式（100×30 / 66×22 / 40×12）、
  标题栏内容、盒子边框、量表字符、去处列表、见闻、8 个页面标题、toast、局部重绘、
  背包光标、坊市货架、帮助浮层、交谈弹层、断路标记、见闻上翻标题、
  面板底色（盒子内部铺色、文字沿用底色、真彩输出含面板 SGR）。
- **舆图**：`render_test.go` 的 `TestMapPageIsDeterministic` —— 连续 12 帧逐字符一致、
  脏行跳过为 0 字节；`TestSortedNodesCurrentWinsOnSameCell` 与
  `TestSortedEdgesBlockedFirst` 固定节点优先级与断路优先。
- **操作**：`ops_test.go` —— 列表光标、使用/装备/卸下、技能装配全量名单、
  买入数量与拦截、私语/回复/历史/空格、文本指令路由、登出两段确认、离开菜单、
  断路原因、战斗选目标与回合保护、交谈选择。

界面测试不依赖真实终端：`render` 返回一块内存字符屏，`frame()` 取纯文本行后断言关键字。

```go
a := testApp()
frame := a.render(100, 30).frame()
if !strings.Contains(frame[0], "青云·樵径") { /* ... */ }
```

- 断言关键字而不是逐字符比对，避免配色/措辞微调导致假红。
- **每行宽度必须等于终端宽**——这是唯一逐字符的硬断言，错一列就意味着中文错位。
- 不做端到端自动化（不驱动真实终端）；真实终端只在手测矩阵里验。

## 6. 离屏快照

```bash
./bin/playcli --server ws://127.0.0.1:8080 --login 沈砚:secret123 \
  --create 沈砚 --snapshot out.txt --color off -w 110 -h 36
```

- 连上服务端等状态就绪（最多 6 秒），再收 700ms 的收尾帧，然后渲染一屏写文件。
- `--color off` 输出纯文本（每行右补空格后去尾），可以直接贴进工单或 diff。
- 不连服务端时导出登录页——用来检查布局改动是否把边框画错。
- 没有 `--record/--replay`：协议帧回放未实现，联调以服务端脚本 + 快照对照为准。

## 7. 复用服务端脚本做联调

服务端仓库 `tools/` 下的脚本可以直接当"对照答案"：

| 脚本 | 能验证客户端的什么 |
|---|---|
| `tools/smoke.mjs` | 登录/建号/打坐/历练的主链路顺序与字段 |
| `tools/travel-check.mjs` | `move` 的受理与到达时刻、地形门槛文案 |
| `tools/party-fight-check.mjs` | `battle` 多怪、目标选择、`pvpResult`、`live` 实时切磋的帧序 |
| `tools/gw-check.mjs` | 宗门战从下书到战果的完整帧 |
| `tools/market-check.mjs` | 交易行挂单/成交/历史的字段 |

做法：先跑脚本看服务端真实输出，再对照客户端渲染；两边不一致时以服务端为准。

## 8. 提测前自查

- [ ] 4004 / 4003 / 4001 / 4029 四种关闭码各有不同处置，且界面上能看到原因。
- [ ] 断线期间所有动作控件置灰，输入不发。
- [ ] 待机时 CPU 接近 0（用任务管理器看，不是凭感觉）。
- [ ] 日志 5000 行时上滚不被新行抢位置（`PgUp` 之后新日志不改变视口）。
- [ ] 80×24 下主流程可用（窄屏单行状态 + 去处 + 见闻）。
- [ ] 100×30 / 120×40 下中文、量表、边框列对齐，无重叠。
- [ ] 终端改成非 UTF-8 代码页时，启动自检给明确提示而不是乱码退出。
- [ ] 没有第二份伤害公式、体力上限、切磋回合数。
- [ ] `go test ./...`、`go vet ./...`、`doc-check` 全绿。
- [ ] 冷启动 ≤ 1 秒（Go 静态二进制），首帧 ≤ 100ms。
