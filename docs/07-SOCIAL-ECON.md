## 1. 推送 vs 请求-响应

| 数据 | 类型 | 客户端刷新方式 |
|---|---|---|
| 聊天 | 推送 `chat` | 追加到对应频道；世界频道保留最近 200 条 |
| 在线人数 | 推送 `presence` | 只更新顶栏数字 |
| 交易行 | 请求 `marketList` / `marketQuery` | 打开 F5 时拉一次；成交后由服务端推 `market` |
| 拍卖 | 请求 `auction op=list` | 打开子标签时拉；出价成功后就地更新该行 |
| 邮件 | 请求 `mail op=list` | 打开子标签时拉；`state` 里只有未读数 |
| 队伍/宗门/好友 | 请求 `party/sect/friend info` | 动作成功后就地刷新，不轮询 |

**不做轮询**：所有列表只在"打开标签页"与"动作回包"两个时机刷新。

## 2. 聊天（`/` 进入输入）

- 四个频道：`world` / `region` / `dm` / `party`；`dm` 需要 `to`。
- 输入 1–80 字符；3 秒冷却（服务端也会拦）。
- 屏蔽是**单向静默**：被屏蔽者的消息对你不显示，但对方不知道；名单存角色上。
- NPC 闲聊带 `npc:true`，用旁白样式（暗黄），不要和玩家发言混在一起。
- 终端里粘贴大段文本要按 80 字截断并提示，不要原样发出去被 `E-BADREQ`。

## 3. 好友 / 师徒 / 关系（F4 子标签）

- 好友申请可离线：对方不在线时申请会落库，登录后重放；界面要显示"待回音"。
- 师徒：师父 ≥ 金丹、徒弟 ≤ 九层；出师要徒弟到筑基；传功每天一次。
- 道侣/仇敌/盟约只做名分，没有任何数值加成——界面文案不要暗示有加成。
- 删除好友/解盟要求对方在线（服务端会拒），失败提示写清"对方不在线"。

## 4. 队伍

- 掉落模式三选一：`free`（最后一击）/ `roll`（抽签）/ `need`（需求优先）。
- 抽签公告由服务端给（"抽签：物品 A 12、B 7 → A 得"），原样展示，不自己判平手。
- 队伍在内存里，重连/重启即散；发现 `party info` 为空时直接回未组队态。

## 5. 宗门与宗门战（F6）

- 建宗要 2 000 灵石（回收口），界面要明确"这是消耗，不退"。
- 宗门战：下书 → 应战 → 报名 → 定名单（3–5 人）→ 开战前 60 秒锁定 → 结算。
- 名单锁定后不可改；锁定后把编辑键位提示改成"已锁定（开战前 60 秒）"。
- 战果 `gw log` 双方可读；战报里的数字（人数、回合、积分、奖池分账）原样展示。

## 6. 交易行（F5）

- 打开标签页：`marketList` 拿挂单与自己的挂单；`marketQuery op=history|curve` 拿历史与曲线。
- 挂单：数量、单价、总价三者联动；费率与在售上限从 `market` 帧的 `feePct` / `maxOpen` 取，不写死。
- 价格曲线：终端里用方块字符画折线；`null` 表示当天无成交，不补 0。
- 自己不能买自己的挂单（服务端拒），界面上把购买键直接灰掉。

## 7. 拍卖

- `list` / `mine` / `sell` / `bid` / `buyout` 五个操作；起拍 ≥ 100，挂单上限 5 件，最小加价 5%。
- 出价会冻结灵石；被超过后全额退回（可能离线，写库）。
- 一口价成交立即结算；无标价时不显示购买键。
- 到期结算由服务端 tick 完成，客户端不做"到点自动当成已成交"。

## 8. 邮件

- 附件是整封领：背包放不下就整封留着，提示"背包空间不足"。
- 有未领附件不能删信；过期信读不到。
- 每日寄信 20 封上限；欢迎信只发一次。

## 9. 错误与文案

- 所有拒绝都要落到具体原因：`E-FULL`（背包/上限）、`E-NOSTONE`、`E-NOITEM`、`E-BUSY`（对方在战斗/不在线）。
- 不要用统一"操作失败"覆盖服务端给的 `msg`；`err.d.msg` 已经是给人看的句子。
- 列表操作失败时保留当前选中行与滚动位置，不要把用户弹回顶部。
