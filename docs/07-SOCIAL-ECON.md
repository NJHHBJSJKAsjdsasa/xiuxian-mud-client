## 1. 推送 vs 请求-响应

| 数据 | 类型 | 客户端刷新方式 |
|---|---|---|
| 聊天 | 推送 `chat` | 追加到对应频道；世界频道保留最近 200 条 |
| 在线人数 | 推送 `presence` | 只更新顶栏数字 |
| 交易行 | 请求 `marketList` / `marketQuery` | 打开"交易"页时拉一次；成交后由服务端推 `market` |
| 拍卖 | 请求 `auction op=list` | 打开子标签时拉；出价成功后就地更新该行 |
| 邮件 | 请求 `mail op=list` | 打开子标签时拉；`state` 里只有未读数 |
| 队伍/宗门/好友 | 请求 `party/sect/friend info` | 动作成功后就地刷新，不轮询 |

**不做轮询**：所有列表只在"打开页面/子标签"与"动作回包"两个时机刷新。
同一页面 5 秒内重复打开不重复请求（用 `last_fetch_ms` 判）。

## 2. 聊天

- 四个频道：`world` / `region` / `dm` / `party`；`dm` 需要 `to`。
- 输入 1–80 字符；3 秒冷却（服务端也会拦）。
- 长文本粘贴：输入行内直接截断到 80 字符并在提示行说明「已截断到 80 字」，不静默改内容。
- 屏蔽是**单向静默**：被屏蔽者的消息对你不显示，但对方不知道；名单存角色上，在社交页"屏蔽名单"里管理。
- NPC 闲聊带 `npc:true`，用旁白样式（暗黄）+ 名字前缀 `【旁白】`，不和玩家发言混排。
- 聊天区在社交页有独立面板（左侧分组底部），可切换频道查看历史；主界面只显示日志里的合并流。

## 3. 好友 / 师徒 / 关系（社交页）

- 左列分组：好友（在线在前）/ 师徒 / 道侣 / 仇敌 / 盟约 / 队伍 / 屏蔽名单；每组带计数。
- 右列详情：道号、境界、在线状态、关系建立时间、可用操作（`↑↓` 选人，`Enter` 执行，不可用的操作显示为弱化色并在提示行写原因）。
- 好友申请可离线：对方不在线时申请会落库，登录后重放；界面显示「待回音」并禁用「再次申请」。
- 师徒：师父 ≥ 金丹、徒弟 ≤ 九层；出师要徒弟到筑基；传功每天一次（操作行显示今日已用）。
- 道侣/仇敌/盟约只做名分，没有任何数值加成——界面文案不要暗示有加成。
- 删除好友/解盟要求对方在线（服务端会拒），失败提示写清「对方不在线」，并把该操作禁用 10 秒。
- `d` 键 → 把选中好友填成私聊对象并进入说话模式。

## 4. 队伍

- 掉落模式三选一：`free`（最后一击）/ `roll`（抽签）/ `need`（需求优先）；`m` 键切换，非队长按了只提示「需要队长权限」。
- 抽签公告由服务端给（「抽签：物品 A 12、B 7 → A 得」），原样展示，不自己判平手。
- 队伍在内存里，重连/重启即散；发现 `party info` 为空时直接回未组队态，并清掉队伍页的缓存。
- 队伍成员行显示字符血条（来自 `battle`/`vital` 的队友部分），没有数据就不画条，不显示 0%。

## 5. 宗门与宗门战

- 建宗要 2 000 灵石（回收口），确认行必须写明「这是消耗，不退」，`Enter` 才提交。
- 宗门战流程用一行步骤条呈现：下书 → 应战 → 报名 → 定名单（3–5 人）→ 开战前 60 秒锁定 → 结算。
- 名单编辑：`Space` 勾选成员加入/移除，实时显示 `3/5`；锁定后整块只读并显示「已锁定（开战前 60 秒）」。
- 战果 `gw log` 双方可读；战报里的数字（人数、回合、积分、奖池分账）原样展示，不做二次计算。

## 6. 交易行

子标签用 `Tab` 轮换：挂单 / 我的挂单 / 历史 / 曲线 / 拍卖 / 邮件。

- 打开页面：`marketList` 拿挂单与自己的挂单；`marketQuery op=history|curve` 拿历史与曲线。
- 挂单：数量、单价、总价三者联动（改任一项算另外两项，取整规则用服务端 `feePct` 算展示值，提交仍以服务端为准），`Enter` 提交。
- 费率与在售上限从 `market` 帧的 `feePct` / `maxOpen` 取，不写死；表单下方显示「手续费 5% · 在售 3/10」。
- 表格列：物品 / 数量 / 单价 / 总价 / 卖家；`s` 按单价排序、`S` 按总价排序，再按一次反向；表头用 `▲▼` 标当前排序列。
- 自己不能买自己的挂单：该行购买操作弱化，提示行写「这是你自己的挂单」。
- 曲线：终端画不了折线，改用**文本表格**（日期 | 均价 | 成交量），空值显示 `—` 而不是 0。
- 撤单：`x` 键撤选中行 + 二次确认（物品会回到背包，背包满则服务端拒）。

## 7. 拍卖

- `list` / `mine` / `sell` / `bid` / `buyout` 五个操作；起拍 ≥ 100，挂单上限 5 件，最小加价 5%。
- 出价会冻结灵石；被超过后全额退回（可能离线，写库）。界面在出价成功后立即把「我的出价」标出来，但余额以随后的 `state` 为准。
- 一口价成交立即结算；无标价时不显示一口价操作项。
- 到期结算由服务端 tick 完成，客户端不做「到点自动当成已成交」。
- 倒计时用服务端时间；剩余 < 1 分钟时数字转朱砂色。

## 8. 邮件

- 双栏（终端窄时上下两段）：左列表（发件人/标题/时间/附件图标/未读点），右详情（正文 + 附件 + 领取/删除）。
- 附件是整封领：背包放不下就整封留着，提示「背包空间不足」，并在详情里标出缺几格。
- 有未领附件不能删信（删除操作弱化并写原因）；过期信读不到，列表里用弱化色并标「已过期」。
- 每日寄信 20 封上限；欢迎信只发一次。
- 写信：收件人道号（可搜索好友）、标题 30 字、正文 500 字、灵石、物品（从背包选，显示可用数量）。

## 9. 错误与文案

- 所有拒绝都要落到具体原因：`E-FULL`（背包/上限）、`E-NOSTONE`、`E-NOITEM`、`E-BUSY`（对方在战斗/不在线）。
- 不用统一"操作失败"覆盖服务端给的 `msg`；`err.d.msg` 已经是给人看的句子。
- 列表操作失败时保留当前选中行与滚动位置，不要把用户弹回顶部。
- 失败提示常驻到手动关闭；连续同类失败合并为一条并显示次数（`背包已满（3 次）`）。
