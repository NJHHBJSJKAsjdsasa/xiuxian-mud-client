## 1. 启动顺序

```
REST 登录            POST /api/login {name, pass}  → 200 {token, hasChar}
   ↓
WS 连接              ws(s)://<host>/ws
   ↓ 5 秒内
hello                {"t":"hello","d":{"token":"...","proto":1}}
   ↓
ready                {proto, minProto, hasChar, player?, catalog, serverNow, ...}
   ↓ hasChar=false
create               {"t":"act","a":"create","d":{"name":"..."}} → ready
```

- token 只存在内存 + `sessionStorage`（可选"记住我"再进 `localStorage`），退出登录必须 `POST /api/logout`。
- `hello` 缺 `proto` 会被当作当前版本：老客户端不会被踢，但新客户端必须带上。
- `ready.serverNow` 用来算时钟偏移：`offset = serverNow - Date.now()`，之后所有倒计时都用服务端时间。

## 2. 协议版本（4004）

| 情况 | 服务端行为 | 客户端行为 |
|---|---|---|
| `proto` 在 `[minProto, proto]` | 正常 `ready` | 进入游戏 |
| 越界 | 先 `err`（`E-BADREQ`，正文带双方版本），再 `4004` 关闭 | **不重连**；整页提示"客户端版本过旧/过新"，显示服务端支持区间 |

- 4004 与 4003 必须分开处理：4003 是 token 失效 → 清 token、跳登录；4004 是客户端要更新 → 清 token 也没用。
- 收到 4004 后不要做指数退避重试，否则会在服务端日志里刷出一串同样的握手失败。

## 3. 心搏

- 服务端 1001 表示心跳超时/写失败；客户端每 25–30 秒发一次 `{"t":"ping"}`（或依赖底层 WS ping 帧）。
- 连续两次心搏无响应，主动关闭并按重连策略处理，不要等 TCP 超时（可能要一分钟）。

## 4. 重连状态机

```
CONNECTING ──open──► HELLO ──ready──► ONLINE ──close(code)──► BACKOFF
     ▲                                  │                        │
     └──────────── 计时到 ◄─────────────┴────────────────────────┘
```

| 关闭码 | 含义 | 处置 |
|---|---|---|
| 1000 | 正常关闭（主动退出） | 不重连，回登录页 |
| 1001 | 心跳超时 / 写失败 | 指数退避：1s → 2s → 4s → 8s，上限 30s |
| 1009 | 帧过大 | 不重连，提示并上报（客户端发了异常帧，属 bug） |
| 1011 | 服务端内部错误（读档失败等） | 退避重连；连续 3 次弹"服务异常，稍后再试" |
| 4001 | 顶号 | **不重连**，提示"账号在别处登录" |
| 4003 | token 失效 | 清 token，跳登录 |
| 4004 | 协议版本不兼容 | **不重连**，提示升级客户端 |
| 4029 | 频率超限被踢 | 60 秒后重连；期间禁用输入 |

重连成功后：

- 用新 `ready` **整体替换** store 的玩家与服务端快照（不要合并旧值）。
- 秘境：服务端口径是 5 分钟内重连回同一层同进度；客户端不需要做特殊处理，`ready` 之后拉一次 `dg info` 即可回到界面。
- 实时切磋、队伍、赶路：服务端重启即散。重连后若 `live` / `party info` 为空，直接回到普通界面并提示一句，不要假装还在。

## 5. 限流与背压

- `E-RATE` 静默处理：连点按钮时不要弹窗，只把按钮置灰到冷却结束。
- 客户端自带动作冷却表（从 `05` 抄），在本地先拦一刀，减少无意义的 `err`。
- 收到 `err` 且 `code=E-COOLDOWN` 时，用 `extra.retryMs`（若有）或本地表刷新倒计时。

## 6. 待确认的实现细节

- `ping` 帧是否需要服务端回 `pong`：当前服务端以控制帧心跳为主，客户端以"两次无响应即重连"为准，不依赖业务层 pong。
- 断线期间用户输入：一律禁用（灰掉动作栏），避免重连后误发一串旧操作。
